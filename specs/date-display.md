# Date display

Approved 2026-10-03, DEC-029. Reuse Settings General rows, AppComboBox, DialogCaption and the existing scheduling components. [Approved proposal](message-library/design/approved/26-date-format-settings.png).

- Follow Windows is the default, including older preference files. Use the current Windows short-date pattern and language.
- Explicit choices: yyyy-MM-dd, dd/MM/yyyy, MM/dd/yyyy and dd MMM yyyy. Examples show 4 October 2026 using Windows month names.
- Save through the protected preference store and update open message tables, observed-count tooltips, activity tooltips, scheduling inputs, receipt summaries and cancellation history.
- Preserve UTC/Local behavior; time-only labels remain time-only. Raw JSON, message payloads and machine-readable exports retain their canonical values.
- The calendar-only field sizes to its formatted label, remains keyboard accessible and read-only to UI Automation, and clears text selection after choosing a day.
- Scheduled eligibility uses a captured typed UTC instant, never the displayed date string. Legacy session receipts are parsed once when restored.

The proposal was generated by editing an actual Settings capture with the built-in image generation tool. Prompt intent: add one compact Date format row beneath General toggles, show the five approved choices with examples, preserve all existing styling and surrounding controls.
